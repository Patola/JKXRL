JKXRL 0.6 - Linux x86-64 Vulkan / SDL3 / OpenXR

This archive contains the same usr/ runtime tree as the Arch release package.
It is dynamically linked against current Arch Linux libraries, NOT a static or
universal Linux distribution. If dependencies are incompatible, build from
source instead: https://github.com/Patola/JKXRL/tree/v0.6

Arch users: prefer jkxrl-0.6-1-x86_64.pkg.tar.zst with:
  sudo pacman -U ./jkxrl-0.6-1-x86_64.pkg.tar.zst
Accept removal of the conflicting older jkxrl-git package if prompted.

Other systems: inspect the usr/ tree and install it into /usr using your
distribution's packaging tools, or (only for an unmanaged installation):
  sudo cp -a usr/. /usr/
Do not overlay a package-managed installation this way. Run ldd on the two
engines/renderers and install compatible dependencies before launching.
Libraries required: SDL3, OpenXR loader, Vulkan loader, zlib, libpng, libjpeg,
libstdc++ and glibc. A Vulkan 1.3+ graphics driver is required separately.

Start your OpenXR runtime and connect your headset first. WiVRn is the primary
tested runtime. Set game paths when outside the default Steam library:
  JKXR_JKA_GAMEDATA="/path/to/Jedi Academy/GameData" jkxr-jka
  JKXR_JKO_GAMEDATA="/path/to/Jedi Outcast/GameData" jkxr-jko

Both original games must be purchased separately. No commercial game data is
included. Launchers refresh VR packs and game modules in the existing per-user
openjk/openjo base directories. Saves and settings are retained; back them up
before upgrading. Do not mix engines/modules/assets from different releases.

Player-facing branding is JKXRL 0.6. Legacy launcher names, environment
variables and paths deliberately remain compatible with earlier releases.
Team Beef/OpenJK attribution and historical tutorial media are retained.

See usr/share/doc/jkxr for release notes, build instructions, settings and
roadmap. Source and license: https://github.com/Patola/JKXRL/tree/v0.6
Bug reports: https://github.com/Patola/JKXRL/issues

Verify downloads against SHA256SUMS from the same release. No cryptographic
signature is supplied; hashes check integrity, not an independent signature.
